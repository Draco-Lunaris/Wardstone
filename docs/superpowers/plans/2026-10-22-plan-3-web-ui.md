# Wardstone Plan 3 (Web UI — Day-to-Day Certificate Operations) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The operator's daily loop — issue, inspect, revoke, download — lives in a browser UI served by ws-web, with admin strictly minimum-viable, no token ever readable by page JavaScript, and the four Plan-2 correctness gaps fixed in passing.

**Architecture:** React + TypeScript SPA prebuilt by Vite, embedded in the ws-web binary and served as static assets (SPA fallback at `/`); ws-web terminates login into a server-side session store (opaque HttpOnly cookie, per-session rotation lock, Authorization injected at the proxy) and relays auth traffic to ws-api over the internal network. Backend gains the read endpoints the UI needs, the OIDC-config/profile-delete/role-assign surface, login tenant pinning, typed revocation reasons, and limiter placement.

**Tech Stack:** Rust workspace (SQLx/Postgres, axum, axum-server+ring) + `ui/` Vite React TypeScript bundle (committed `ui/dist`, embedded via `include_dir`), tower-governor GCRA, no new Node tooling in release images.

**Spec:** `docs/superpowers/specs/2026-10-22-plan-3-web-ui-design.md` (binding authority; this plan argues from it — executors read both).

## Global Constraints

- Spec: browser talks ONLY to ws-web; ws-web path-proxies `/api/v1/*` to ws-api; ws-api publishes NO ports in the default bundle (compose unchanged on ports).
- Anti-goal: no JWT/refresh/API token in `localStorage`, `sessionStorage`, or any JS-readable cookie; the sanctioned exception is the transient one-time display/download of a server-generated key (memory only, never persisted, never logged).
- Anti-goal: no client-side cryptography. Parsing PUBLIC certificate PEMs in JS (fields only) is allowed; keys never parsed.
- House rules: `cargo fmt --all` clean; `cargo clippy --workspace --all-targets -- -D warnings` clean; no `unwrap()`/`expect()` outside `#[cfg(test)]`; short conventional commits; **no AI co-author attribution**.
- Migrations ADD-ONLY (`crates/ws-core/migrations/`); `REQUIRED_MIGRATION_COUNT` in `crates/ws-core/src/db.rs` bumps with each; never edit an applied migration.
- DB-gated suites take unique advisory keys from `0x0057_4144_5354_00xx`: 0003–0011 taken; **this plan takes 0012 (`oidc_test.rs`) and 0013 (`session_test.rs`)**; sweeps FK-first before each test and deletes its rows at the end of each test; DB `postgres://wardstone:wardstone@localhost:5432/wardstone_test`; run `-- --include-ignored`.
- Serialized DTOs: `#[serde(rename_all = "snake_case")]`; TEXT-stored enums: `as_str()` == serde name, written once.
- `aws-lc-rs` must never enter the graph (ring provider pinned).
- The setup page (`/setup`, page.rs, tls.rs) is untouched except where Task 8 pins the SAN validation inside `run_setup`.
- Workspace dependency pins: each task pins only what it uses, with an inline rationale at the pin site (new pins expected only: `include_dir` on ws-web, governor/tower-governor already pinned from Plan 2).

## Review Focus

Inputs the spec implies but no single task covers by default — each line's test is pinned in the owning task:

1. **Concurrent expired-session requests race the one-shot refresh rotation** (second tab must not spuriously log out) → Task 11's concurrent-rotation test (`both_concurrent_rotations_succeed`).
2. **Free-text revocation reason silently dropping the CRL reason extension** → Task 4's worker-facing test (`typed_reason_reaches_crl_contract`).
3. **OIDC CSRF-state round-trip must survive the ws-web relay** (state minted by ws-api consumed only at ws-api; callback arrives via ws-web public URL) → Task 5's start/callback tests + Task 11's relay test.
4. **SPA fallback swallowing API/auth 404s or asset paths** → Task 10's precedence tests (`spa_fallback_never_masks_api`).
5. **Cookie discipline on every Set-Cookie path** (HttpOnly, Secure, SameSite=Lax, Path=/) → Task 11's `session_cookie_flag` test asserting all four attributes.
