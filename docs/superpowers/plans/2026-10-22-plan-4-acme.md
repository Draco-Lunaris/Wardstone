# Wardstone Plan 4 (ACME — First-Party RFC 8555 Server) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** homelab machines renew automatically — Wardstone speaks ACMEv2 (RFC 8555) natively, first-party (no ACME crate), with the same issuance policy as the manual path.

**Architecture:** a new `ws-acme` crate holds the protocol machinery (RFC 8555 types, first-party JWS verification atop the existing jsonwebtoken pin, in-memory nonce store, challenge/authorization state machine); `ws-api` mounts `/acme/<tenant>/…` routes that delegate issuance to the EXISTING `issue_in_tx` path with an `AcmeAccount` actor; `ws-web` path-proxies `/acme/*` like `/api/v1/*`; challenges verify synchronously in-request (HTTP-01 server-fetch, DNS-01 native resolve).

**Tech Stack:** existing Rust workspace; jsonwebtoken (workspace pin — JOSE codec only, not ACME machinery); a native DNS resolver (builder choice, std-first); tower-governor GCRA; no new ACME dependencies.

**Spec:** `docs/superpowers/specs/2026-10-22-plan-4-acme-design.md` (binding; the Builder-Check Settlements section has the force of operator rulings). Executors read both.

## Global Constraints

- Spec: **no third-party ACME crate** anywhere; JOSE primitives may reuse the existing jsonwebtoken workspace pin.
- Spec: ACME-issued certificates obey the SAME profile constraints (`validate_names`, profile key-usage/EKU/lifetime/SAN patterns) as the manual path — divergence of policy is an anti-goal.
- Spec: the CA never trusts client-supplied challenge results — HTTP-01/DNS-01 verify from the server's own connection/resolution with the server-computed `keyAuthorization`; `Host`/forwarded headers are never trusted for identifier binding or URL construction (absolute URLs from `WARDSTONE_PUBLIC_URL`).
- Spec: URL shape is Plan-1-pinned `/acme/<tenant>/…` (directory, kid URLs carry the tenant segment); v1 operates on the setup tenant; `acme_accounts` PK = `(tenant_id, jwk_thumbprint)`.
- Spec: enrollment posture = OPEN on reachable networks (operator-settled); per-account status gate is the control surface (pending refuses orders; deactivated refuses everything); CIDR gate/pre-registration = recorded follow-ups.
- Spec: authorization reuse per `(account, identifier)` with a 30-day valid window; unlimited challenge re-POSTs while pending (expiry ≈ 7 days); order invalidates when any authorization invalidates; challenge verification backs off per-authorization.
- Spec: revocation = account-key JWS only in v1 (cert-key PoP declined, RFC-sanctioned error); deactivation invalidates PENDING authorizations, blocks orders, leaves issued certificates.
- Spec: ToS optional via `WARDSTONE_ACME_TOS_URL`; verification is synchronous in-request; ws-worker untouched.
- House rules: `cargo fmt --all` clean; `cargo clippy --workspace --all-targets -- -D warnings` clean; no `unwrap()`/`expect()` outside `#[cfg(test)]`; short conventional commits; **no AI co-author attribution**; serde `rename_all = "snake_case"` + `as_str()` == serde name on TEXT-stored enums.
- Migrations ADD-ONLY: 011 (ACME tables) then 012 (capability seed); `REQUIRED_MIGRATION_COUNT` → 11 → 12; never edit applied migrations (migration 010's missing trailing newline must NEVER be "fixed").
- DB-gated suites: next free advisory key `0014` (0003-0013 taken); sweep FK-first before each test, DELETE rows at the end of each test; DB `postgres://wardstone:wardstone@localhost:5432/wardstone_test`; run `-- --include-ignored`.
- `aws-lc-rs` never enters the graph.
- IssueCertificateBody contract note: `POST /api/v1/certificates` answers 200 (json_no_store) — same handler ACME finalize reuses.

## Review Focus

1. **Client-supplied challenge answers are never trusted** (the server computes the expected `keyAuthorization` from ITS stored token + the account's thumbprint) → pinned by `dns01_rejects_client_suggested_payload` + `http01_verifies_from_server_side_fetch` (Task 10).
2. **Replay-nonce single-use on every mutating request, including error responses** (a spent nonce returned with a fresh one; a mutating request without a valid nonce is `urn:ietf:params:acme:error:badNonce` before any state read) → `nonce_is_single_use_even_on_failure` + `mutating_request_without_nonce_rejected` (Task 8).
3. **JWS identity traps**: an `embedded-jwk` payload presenting a `kid` header (or vice versa) is rejected; a `kid` URL from another tenant is a lookup failure, not a cross-tenant account → `jwk_header_with_kid_rejected` and `kid_from_other_tenant_fails_lookup` (Task 8).
4. **Same-policy issuance**: an ACME finalize whose SANs violate the profile's patterns fails exactly as the manual path does (`not_permitted_by_profile` semantics, ACME problem-document) → `acme_finalize_respects_profile_san_policy` (Task 11).
5. **Same-bucket abuse on the unauthenticated surface**: new-account is gated by per-IP GCRA even before any account exists; a spent authorization cannot be re-verified after its window → `new_account_is_rate_limited_per_ip` (Task 9) + `reused_authorization_respects_window` (Task 10).
